# Phase 4-1：MIDI 预览与媒体任务

## 需求

用户在 `config/user-config.json` 选择音乐模块后，启动本地服务并上传 MIDI，服务必须使用所选的渲染器、播放器适配器和媒体编码器。生成结果要能在任务查询和曲库接口中预览，并且媒体的实际格式、文件后缀和 HTTP 响应类型一致。

用户配置的时区也必须同时用于信件和 MIDI 任务的自然日统计。服务重启后，已经生成的任务和媒体仍应可以查询和读取。

本轮不处理原生 WebPlayer 无法接管本地曲目的问题，不修改游戏专有文件，也不新增 GUI。

## 设计

- `loadUserConfig()` 在默认模块设置上合并 `music`、`media` 和 `threeD` 选择；用户配置存在时，这些选择与信件选择一起成为启动时的运行设置。
- 启动器把用户时区传给 `MidiJobService`，并把 FFmpeg 路径作为编码器选项传入。
- 编码器声明自己的媒体扩展名和 MIME 类型。MP4 编码器生成 `.mp4` 与 `video/mp4`；未选择编码器时保留 WAV 字节并使用 `.wav` 与 `audio/wav`。
- 网关按任务服务声明的媒体类型提供 GET、HEAD 和 Range 响应；持久化任务恢复时沿用当前运行配置生成媒体 URL。

## 验收标准

1. 用户配置中的音乐模块选择能在本地启动装配中被实际解析，并可被测试替换实现观察到。
2. 用户时区被 MIDI 服务采用，自然日统计在非默认时区边界下正确。
3. WAV 和 MP4 两种任务的文件后缀、媒体字节和响应 `Content-Type` 相互一致。
4. 任务列表、单任务查询、曲库查询、媒体 GET/HEAD/Range 及服务重启读取全部通过回归测试。
5. `pnpm test` 和 `git diff --check` 通过；不涉及 Steam 实机验收。
