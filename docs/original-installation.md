# 原装游戏基线与插件接入

林离·余音最终交付的是建立在《BSide: Olivia Lin》本体之上的插件。插件不会把某个已经被其他工具改过的游戏目录当成开发依据，也不会把游戏原始资源提交到仓库。

## 当前调查结论

- Steam 本体识别为 AppID `4532590`，客户端版本为 `0.0.9.627`，当前本地 manifest 的 buildid 为 `24943426`。
- 当前游戏目录中的 `feapp.dat`、`webplayer.dat`、`NutStudioUI.dll` 和 `NutContainerPlugin.dll` 与 OliviaSoul 在补丁前保存的原版备份不同。
- 原版 `feapp.dat` 的 11 个兼容接口仍指向官方远端路径；当前目录的同一批接口已指向本地 `/toy` 路由。这是第三方修改的明确信号。
- 因此，当前目录只能作为“已修改样本”用于分析，不能重新生成原装哈希基线。

仓库只保存文件路径、版本信息和 SHA-256，不保存游戏资源。`config/client-baseline-0.0.9.627.json` 的前四项哈希来自 OliviaSoul 的原版备份，其他项目来自同一 Steam 安装中未被该工具替换的文件，并在配置中注明了来源。

## 插件安装时的流程

1. 定位游戏根目录，并读取根目录 `version.json`。
2. 校验版本白名单和 Steam 本体文件基线。
3. 将安装状态分为 `pristine`、`modified`、`unknown` 和 `unsupported-version`。
4. 只有 `pristine` 才进入补丁规划；检测到其他工具修改、无法识别的变化或未知版本时停止，并提示用户先用 Steam 验证游戏文件或恢复原版。
5. 在写入前创建独立备份、记录清单和哈希；卸载或回滚只恢复插件自己管理的文件。

开发阶段可以使用受控的 `modified` 样本继续做只读分析，但不能把它作为发布安装器的成功条件。这样既能复用现有的 MIDI、信件和网关代码，也能保证发布版插件以原装游戏为输入。

开发阶段如需接入游戏，使用 `scripts/stage-client.ps1` 创建独立物理副本，并用 `scripts/patch-staged-client.mjs` 在副本上写入补丁。补丁脚本会再次校验原装基线；当前游戏目录不会被写入。`-UseHardLinks` 只适合快速分析，不应作为启动测试副本。

## 与 OliviaSoul 的关系

OliviaSoul 的原版备份和接口行为是本项目的调研证据，不是本项目的运行时前置条件。用户不需要先安装 OliviaSoul；如果检测到它已经修改过游戏，本项目应要求用户恢复原版后再安装，避免两个补丁器互相覆盖。
