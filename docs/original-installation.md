# 原装游戏基线与插件接入

林离·余音最终交付的是建立在《BSide: Olivia Lin》本体之上的插件。插件不会把某个已经被其他工具改过的游戏目录当成开发依据，也不会把游戏原始资源提交到仓库。

## 初始调查结论（历史样本）

- Steam 本体识别为 AppID `4532590`，客户端版本为 `0.0.9.627`，当前本地 manifest 的 buildid 为 `24943426`。
- 当前游戏目录中的 `feapp.dat`、`webplayer.dat`、`NutStudioUI.dll` 和 `NutContainerPlugin.dll` 与 OliviaSoul 在补丁前保存的原版备份不同。
- 原版 `feapp.dat` 的 11 个兼容接口仍指向官方远端路径；当前目录的同一批接口已指向本地 `/toy` 路由。这是第三方修改的明确信号。
- 因此，当前目录只能作为“已修改样本”用于分析，不能重新生成原装哈希基线。

仓库只保存文件路径、版本信息和 SHA-256，不保存游戏资源。`config/client-baseline-0.0.9.627.json` 的前四项哈希来自 OliviaSoul 的原版备份，其他项目来自同一 Steam 安装中未被该工具替换的文件，并在配置中注明了来源。

后续样本状态已变化：2026-09-09 核查时 `webplayer.dat` 已与原版基线一致，不能继续按上述初始快照认定它仍被修改。最新文件哈希与原生证据见 [Phase 4-3](./phase4-3-native-webplayer-evidence.md)。

## 当前交付边界（2026-09-09）

已接入的 Steam 0.0.9.627 客户端通过了上传 MIDI、歌单演奏与试听验收，服务启动也有 PowerShell/CMD 包装入口。但这些证据不等于首次从原版安装已能一次完成。

本轮使用 SHA-256 与基线匹配的原版备份，在内存调用 `applyFrontendPatch`（启用 MIDI 和离线功能），没有写入游戏目录。结果确认：

- `install-executor.js` 调用的完整补丁入口只应用基础离线开关与试听映射，尚未整合 `OFFLINE_USER_SONG_PATCHES` 及其余 MIDI 增量；缺少用户曲目查询、上传提交、离线页签和歌单媒体回退等修复。
- 对该产物直接运行 `applyOfflineMidiFeaturePatch` 仍会在 `offline-user-song-recovery-dedupe(0/1)` 拒绝：旧脚本要求曾出现于开发安装样本的三次重复轮询签名，不能直接套到原版安装产物。
- Phase 7 安装实现前应复用当前补丁表，区分原版输入与已知增量输入，整合恢复轮询及所有必要补丁，并验证从原版生成的产物具备相同功能、签名不符安全拒绝、备份回滚及用户安装流程。不能通过放宽未知签名校验来绕过问题。

上述整合是新机器交付前的必要工作，不能宣称 clone 后仅启动服务就会自动修复尚未接入的原版游戏。本次仅盘点和记录该边界；当前客户端功能的 Phase 4-1 至 4-4 验收保持有效。

## 插件安装时的流程

1. 定位游戏根目录，并读取根目录 `version.json`。
2. 校验版本白名单和 Steam 本体文件基线。
3. 将安装状态分为 `pristine`、`modified`、`unknown` 和 `unsupported-version`。
4. 只有 `pristine` 才进入补丁规划；检测到其他工具修改、无法识别的变化或未知版本时停止，并提示用户先用 Steam 验证游戏文件或恢复原版。
5. 在写入前创建独立备份、记录清单和哈希；卸载或回滚只恢复插件自己管理的文件。

开发阶段可以使用受控的 `modified` 样本继续做只读分析，但不能把它作为发布安装器的成功条件。这样既能复用现有的 MIDI、信件和网关代码，也能保证发布版插件以原装游戏为输入。

开发阶段如需接入游戏，使用 `scripts/stage-client.ps1` 创建独立物理副本，并用 `scripts/patch-staged-client.mjs` 在副本上写入前端补丁。原生入口检查则由 `scripts/patch-native-features.mjs` 写入；运行它前必须先完成备份并确认游戏进程已退出。补丁脚本会对 DLL 签名逐一校验，当前游戏目录不会被暂存流程写入。`-UseHardLinks` 只适合快速分析，不应作为启动测试副本。

## 与 OliviaSoul 的关系

OliviaSoul 的原版备份和接口行为是本项目的调研证据，不是本项目的运行时前置条件。用户不需要先安装 OliviaSoul；如果检测到它已经修改过游戏，本项目应要求用户恢复原版后再安装，避免两个补丁器互相覆盖。
