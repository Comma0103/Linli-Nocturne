# 需求基线

## 必须交付

1. 游戏内写信入口和本地文字回信。
2. 默认每日最多 3 封、最短延迟 5 分钟，并提供关闭限制的开关。
3. 外部模型 API、本地模型和无模型降级路径。
4. SQLite 信件、记忆、队列和失败重试；记忆必须可关闭并限制保存条数、单条长度和注入上下文长度。
5. MIDI 上传、校验、解析、延音踏板、音频生成和本地曲库。
6. 文字、视频、音频和未来 3D 演奏使用统一媒体任务模型。
7. 已有 MP4 视频回信导入、播放、替换、删除和备份。
8. 面向普通用户的安装器、配置向导、模型选择、日志、备份和恢复。

## 模块化与可插拔要求

1. 核心流程只依赖稳定的接口和统一中间表示，不得把某个外部项目、模型服务、渲染器或游戏插件写死为唯一实现。
2. 每个可替换模块都必须有能力描述、配置校验、统一错误状态和可测试的 fake 实现。至少包括信件 provider、MIDI 演奏器、音频/视频/3D 渲染器和未来的动作同步器。
3. App 和设置界面必须保留模块选择入口。用户可以为每个模块选择外部 API、本地实现、第三方 Harness、内置实现或 fallback；不可用时要给出清楚的错误和切换选项。
4. 第三方项目只通过适配器接入。适配器负责把第三方输入输出转换成项目统一接口，领域服务不直接依赖第三方目录结构、Prompt、数据库或运行时文件。
5. 模块配置、选择结果和版本信息应可导出、备份和恢复；敏感凭据只进入安全配置或运行时环境，不进入信件、媒体元数据、日志和 Git。

## 最终目标

- 规则化和模型辅助的即兴 MIDI 创作。
- 可替换的 LetterProvider、MusicPlayer、AudioRenderer、VideoRenderer、Future3DRenderer。
- MIDI 到林离 3D 演奏视频的可扩展接口。
- 手指、音符、镜头、动作和音色的同步控制。
- 成熟后公开源代码、人格资料和样例信件。

## 边界

不分发米哈游原始资源、修改后的二进制文件、用户隐私数据和 API Key；不绕过 DRM。
