# Phase 2：游戏接入

## 已开始

- 版本白名单和未知版本拒绝。
- 客户端关键文件 SHA-256 基线校验。
- 变更状态可区分为 `missing`、`unchanged` 和 `changed`。
- 独立备份目录、备份清单和带完整性校验的回滚。
- 已在真实 0.0.9.627 游戏目录上完成只读 dry-run：版本识别正确；进一步对照 OliviaSoul 的原版备份后确认，当前目录是已修改样本，不能作为原装基线。
- 已固化原装基线来源和安装状态识别：原装、第三方修改、未知变化、未知版本会被区分，发布补丁只接受原装状态。
- 已建立前端压缩资源的补丁规划和构建链：先校验唯一 `main-*.js`、接口出现次数和补丁标记，再在内存构建输出包。
- 对当前安装目录的 `feapp.dat` 检查显示，11 个信件/歌单接口均已是本地 `/toy` 路由；这被记录为第三方修改信号，不能作为原装输入。
- 已对原版前端完成 MIDI 流程审计：确认上传地址、生成、单任务查询、列表、取消、删除、批量查询和用户曲目查询接口，并确认离线模式的入口与轮询限制。
- 已实现本地 MIDI 上传地址、文件接收、MIDI 解析、WAV 生成、任务查询、媒体读取和取消/删除的网关契约；任务元数据和媒体路径已支持 SQLite + 文件目录持久化，前端 MIDI 路由支持显式开启补丁。
- 已对原版 `feapp.dat` 完成只读补丁 dry-run：20 个兼容路由和 13 组离线功能签名全部通过数量校验，补丁只在内存中生成，没有写入游戏目录。
- 已加入独立暂存副本脚本：默认进行物理复制，再替换已确认的原版资源；可选 `-UseHardLinks` 仅用于快速分析，避免把硬链接副本误当成可启动测试目录。脚本不会写入当前游戏目录。
- 已将补丁写入独立物理暂存副本：副本先通过原装基线校验，再写入 20 个兼容路由和 13 组离线功能补丁；回读校验显示只有 `feapp.dat` 发生预期变化。
- 已执行暂存副本启动冒烟：启动器能够正常启动并退出，但在当前无完整 Steam 运行上下文的环境中没有留下游戏进程，因此信件/MIDI 的真实界面联调仍需在 Steam 客户端上下文中完成。
- 已修复真实 CEF 客户端的凭据 CORS 预检：动态允许 `Origin` 和客户端声明的自定义请求头，实测已从 `OPTIONS` 进入 `GET /toy/searchPlaylist` 与 `GET /toy/letter/unread_count`。
- 已将原生离线入口检查整理为带签名校验的 DLL 补丁模块和可重复脚本，并在当前 Steam 安装的受控备份后写入 `NutStudioUI.dll` 的 4 个检查点和 `NutContainerPlugin.dll` 的 1 个检查点；游戏通过 Steam 重新启动后已加载信件和曲库组件请求。
- MIDI 任务现在携带统一 `RenderJob` 的 `status`、`progress`、`attempt`、`errorCode`、渲染器标识和版本，并在 SQLite 重建服务后保持这些字段；`searchUserSongs` 已接入本地已完成任务并支持游标分页。
- 已修复真实客户端上传链路的第一处协议不兼容：原版响应拦截器要求 `code: 0` 和 `data` 外层，原网关的 MIDI 上传地址响应未满足该契约，导致游戏在真正发出文件上传请求前直接显示“网络错误”。现在上传地址、生成、查询、列表、批量查询、取消和删除接口均按客户端外层格式返回，并兼容原版的下划线请求字段和数字任务状态；新增回归测试覆盖两种字段命名、预检、分页和失败任务。
- Steam 实测已确认上传和生成任务均成功；针对 0.0.9.627 精简模式偶尔丢失批量查询任务 ID 的情况，批量结果接口增加了最近任务回退和数组参数兼容，避免任务完成后曲库界面收不到结果。
- 进一步确认游戏界面仍用离线状态遮挡用户曲目：已对带有本项目标记的现有前端包增加受控增量补丁，允许离线模式加载用户曲目并在曲库中优先显示；补丁前会单独备份当前包，避免覆盖已有接入。
- Steam 第二次实测显示任务仍能生成，但离线定制弹窗使用了在线任务处理器，且重新进入定制页没有恢复历史任务；增量补丁已改为使用 Lite 本地任务处理器，并在进入定制页时恢复本地任务轮询，避免再次消耗上传额度来验证已有任务。
- 针对第三次实测中“定制弹窗可打开但曲库主区仍为空”的现象，已增加提交后的 Lite 任务刷新，并让离线模式始终渲染“用户上传”曲目页签；这样生成任务完成后可以从本地任务/用户曲目链路回读，而不依赖在线模式的曲库请求。
- 后续实测发现离线占位提示仍会遮挡用户曲目，已进一步让“我的上传”在离线模式默认选中并自动加载，同时仅对非用户曲目页显示离线占位提示；实测已看到两条 `linli-smoke.mid` 恢复记录。
- 已定位并修复用户曲目“下载中 0B/0B”：原界面把网关生成的曲目交给只认识原始曲库 ID 的原生下载器；现在用户曲目直接使用本地网关媒体 URL，并标记为可播放资源，避免进入永不完成的原生下载状态。
- 已通过 `NutStudioUI.dll` 反汇编确认播放桥接契约：Lite 模式的 `play` 命令必须携带 `song` 对象，原生层会把它序列化后交给 WebPlayer；此前直接改成 `{cmd:"play",url:...}` 会被原生层当成缺少歌曲对象处理。当前补丁恢复 `song` 结构，只把本地媒体地址放入歌曲的 `videoUrl`（必要时回退到 `audioUrl`）。
- 首次将 WebPlayer 的 `video` 元素替换为 `audio` 后出现桌面黑屏，已根据实测恢复 WebPlayer 原始备份；该方案不再采用。当前播放协议修复也已改为自动迁移回原生 `song` 契约，尚待重启游戏重新验证。
- 最新 Steam 实测确认：用户曲目可以通过“加播单”加入音乐桌面；这不能证明“演奏”请求已经成功。桌面人物仍保持待机，演奏请求和本地媒体呈现链路仍需单独验证。另已补齐歌单时间字段，避免显示 `Invalid Date`。
- 已补充本地媒体兼容回退：用户曲目缺少 `videoUrl` 时，曲库构造的 `song` 对象会使用 `audioUrl`；补丁器同时支持从前一版错误 URL 命令状态幂等迁移回原生 `song` 契约。
- 已确认上传曲目演奏失败的直接原因：CEF 控制台报告从 HTTPS 游戏页面请求 `http://127.0.0.1` 媒体时发生 mixed content 拦截。当前运行时将用户曲目的 `videoUrl`、`audioUrl` 和 `videoByTodView` 改为可信的 `http://localhost` 回环地址，并补齐每个 TOD 条目的 `duration` 字段；API 仍保持原有 `127.0.0.1` HTTP 兼容地址。HTTPS 媒体端点保留为可选部署方式，不作为当前客户端默认路径。
- 回环媒体请求路径确认后，日志进一步确认原生 `play` 命令已发出但 WAV 没有产生 `timeupdate`；官方页面使用 `<video>` 播放器，因此本地音频现在会封装成音频轨 MP4（不添加画面轨），并以 `video/mp4` 返回，避免把“能发出播放命令”误判为“播放器已开始播放”。
- 原生桥接还要求 `VideoTodViewItem.duration` 为整数秒；本地任务保留小数时长用于音频和任务记录，但发送到原生层时会转换为整数，并在媒体服务端记录实际请求字节数，便于区分证书、网络和播放器解码问题。
- 官方曲库的第二个 TOD 键是字面量 `TOD1730`，不是 `TOD17`；用户曲目已按官方的 `TOD12 / TOD1730 / TOD20` 组合生成。媒体 GET 目前会记录方法、Range、状态、Content-Type 和字节数，先用于确认原生是否真正发起请求，再决定是否补充 Range/HEAD 协议。
- 根据实测“上传曲目 play 命令已到达，但旧曲目继续 timeupdate”的诊断，已为本地媒体增加官方风格的 `.mp4` URL 别名，并实现 `HEAD 200`、单段 `Range` 的 `206 Partial Content`、`Content-Range` 和 `Accept-Ranges`；旧的无后缀 URL 仍兼容。该改动只覆盖媒体协议层，尚未宣称原生 WebPlayer 已完成切歌。
