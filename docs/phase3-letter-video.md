# Phase 3-5：视频回信资产流程

## 需求与范围

为已经有文字回复的信件导入用户已有 MP4，提供本地管理页的选择、预览、替换、删除和可读错误。视频是附属资产，不改变信件的每日额度、等待时间、文字回复或重试状态。本轮不生成视频，不实现 3D，也不宣称原版 Steam 客户端已经显示或播放成功。

## 设计

- `VideoImportAdapter.inspect(path)` 返回统一的格式、时长、宽高和编码信息。默认 `ffprobe.mp4` 复用 FFprobe 检查 MP4/H.264/yuv420p 与可选 AAC 音轨，可通过 ModuleRegistry 和设置向导选择其他已注册实现。FFprobe 不可用时返回明确错误。
- 上传流限制为 100 MiB，默认最长 10 分钟；先写入独立媒体目录的临时文件，验证通过后再发布。文件名由资产 ID 生成，用户文件名只作为显示名称，不作为路径。
- 视频导入使用 RenderJob 的 queued → validating → rendering → produced → published/failed 状态；界面显示“处理中、可播放、失败”。SQLite 保存任务和每封信当前生效资产的关联，领域服务不保存网关绝对地址。
- 同一封信同时只允许一个导入任务。替换期间旧视频继续可读，成功后事务切换关联；失败保留旧视频。替换/删除只解除当前关联，旧文件保留为备份，管理接口不公开旧资产。备份恢复需要同时保存 SQLite 和媒体目录；自动清理历史文件留待统一备份工具。
- 服务异常退出的导入可在超时后恢复为失败，再重新上传；迟到的旧任务不能覆盖新任务或删除后的关联。文字回信不受影响。
- 新增本地 `/letter/video/…` 管理接口、GET/HEAD/单段 Range 媒体读取和 `/letters/videos` 页面。只向游戏兼容响应附加 `replyVideoUrl`，保持既有 `replyType`，不猜测原生视频类型枚举。游戏显示契约及实机验收在 Phase 3-6 单独确认。

主要接口：`PUT /letter/video/upload/:letterId` 导入或替换，`GET /letter/video/status/:jobId` 查询状态，`GET /letter/video/list?letterId=...` 查看任务，`GET|HEAD /letter/video/media/:assetId.mp4` 播放/读取，`POST /letter/video/delete/:letterId` 删除当前关联，`GET /letters/videos` 打开本地管理页。

## 验收标准

1. fake 适配器和默认 FFprobe 适配器均通过统一接口接入；未知实现拒绝，旧设置缺少新字段时使用默认值。
2. 有效 MP4 可导入、查询状态、播放、重建服务后读取、替换和删除；文件保存在游戏目录外。
3. 扩展名伪装、无视频轨、错误编码、零时长、超时长、超大小和工具缺失得到明确错误，不损坏旧视频。
4. 并发导入/删除得到冲突，超时恢复后的迟到结果不能发布；失败重传仍可成功。
5. GET/HEAD/Range 返回正确类型和长度，删除后地址返回 404；API 不泄漏本地路径。
6. 通过网关端到端测试、真实工具生成的合成视频验证和本地管理页检查；不把自动化结果记成用户 Steam 实机验收。

## 使用与边界

运行入口和设置见 [模块设置](./module-settings.md)。默认工具只进行容器/流元数据检查，不保证每一帧均可解码；页面的播放失败提示和完整游戏验收仍必要。数据目录应放在 Steam 目录外；当前历史视频保留占用磁盘，不提供自动清理。最终 App 的安装、凭据管理、全部模块图形设置及视频生成依旧未完成。
