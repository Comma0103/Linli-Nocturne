# Phase 4：完整音乐体验总览

Phase 4 负责把用户曲目从“能够上传、生成和在本地曲库显示”推进到普通玩家可以在 Steam 游戏中预览、播放和尝试演奏。`LINLI-PLAY-001` 是本阶段的跨层阻塞：只有获得原生 WebPlayer 的只读反汇编、CEF 媒体事件或完整媒体请求证据后，才继续定位。

## 路线

| 路线项 | 内容 | 状态 |
| --- | --- | --- |
| Phase 4-1 | 用户 MIDI 预览、音频/视频任务、轮询、取消和失败恢复 | 进行中；首轮已打通音乐配置与媒体契约，详见 [Phase 4-1 音乐设置与媒体契约设计和验收](./phase4-1-music-settings-and-media.md) |
| Phase 4-2 | 用户曲库、歌单和模块选择入口 | 待开发 |
| Phase 4-3 | `LINLI-PLAY-001` 原生 WebPlayer 只读证据调查 | 待开发 |
| Phase 4-4 | 上传曲目在 Steam 中真正播放/演奏的验收 | 待开发 |
| Phase 4-5 | 网易云音乐、QQ 音乐等外部歌单/歌曲导入适配器 | 待开发 |
| Phase 4-6 | 不要求逐帧手指匹配的音频播放和近似 MIDI 演奏模式 | 待开发 |

## 外部来源和版权边界

外部音乐服务通过可替换适配器接入，只保留统一的曲目中间表示和能力报告。实现只处理用户有权使用、能够合法导出的内容，不绕过 DRM、登录保护或地区限制；来源适配器不能写死进 MusicService。

Phase 4-6 的“宽松演奏”只要求歌曲能播放、MIDI 事件能驱动可用的演奏入口，不要求手指、琴键、镜头和动作逐帧一致。严格同步属于 Phase 6 的独立时间轴和可插拔 3D Renderer 工作。
