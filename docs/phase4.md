# Phase 4：完整音乐体验总览

Phase 4 负责把用户曲目从“能够上传、生成和在本地曲库显示”推进到普通玩家可以在 Steam 游戏中预览、播放和尝试演奏。2026-09-09，4-1 至 4-4 已完成：`LINLI-PLAY-001` 已定位、修复并通过 Steam 实机验收，歌单与试听也已复验。2026-09-11，收尾提交完成预设歌单元数据/封面回退、在线测试配置与 MIDI `bypass` 的回归，用户确认本轮 Steam 实机验收通过。4-5 至 4-7 尚未完成。

## 推进方式：有依赖的交叉推进

Phase 4 的 7 个编号是 7 个开发与验收主题，不是必须一个全部结束后才允许开始下一个的流水线。正确的关系是：

| 里程碑 | 可以提前开展的工作 | 完成所需的前置条件 |
| --- | --- | --- |
| 4-1 音乐设置与媒体任务 | 基础实现、任务生命周期、格式契约和自动化验证 | 本地任务、媒体读取和恢复验收完成；客户端体验仍需单独确认 |
| 4-2 曲库、歌单和模块入口 | 在 4-1 接口稳定后并行补齐曲库、歌单和真实启动入口 | 依赖 4-1 的任务和媒体接口；用户路径与重启行为分别验收 |
| 4-3 原生 WebPlayer 证据调查 | 可与 4-1、4-2 并行进行只读样本、日志和调用链调查 | 只需有可复现的曲目/媒体输入；不能直接修改原生文件 |
| 4-4 Steam 播放/演奏验收 | 在 4-1、4-2 有可测试产物后准备验收脚本 | 4-3 提供足够证据，且用户确认实际 Steam 结果 |
| 4-5 外部音乐导入 | 可提前调研来源能力，但实现接入要复用内部曲目表示 | 4-1 的媒体任务和 4-2 的曲库入口稳定 |
| 4-6 宽松演奏 | 可在 4-1/4-2 的播放入口上做方案验证 | 相关播放链路和模块选择完成；不把它写成精确 3D 演奏 |
| 4-7 总验收与交接 | 汇总前六项证据 | 4-1 至 4-6 各自达到明确的完成标准 |

因此，4-2 和 4-3 可以在 4-1 尚未整体宣告完成时推进，但不能把局部自动化通过写成 4-1 或 4-2 已完成；4-4 以及总验收仍受前置条件约束。后续每轮记录“本轮完成项、依赖项、尚未满足的验收门槛”，复选框只表示该里程碑整体通过。

本轮收尾只关闭已实现的 4-1 至 4-4 回归问题，不改变 4-5 外部来源、4-6 宽松演奏或 4-7 总体验收的状态。当前实现已合入 `main`，并由 `phase4-steam-acceptance-v1.0.0` 标记。

## 下一步与保留边界

下一步进入 Phase 4-5 的调研和设计：先盘点现有 Importer、MusicService、曲目表示和媒体服务，再核查外部来源的导出能力、成熟项目与许可，明确“只有曲目信息”和“确有可播放媒体”的区别，确定最小实现及验收标准后开发。本次盘点不提前实现外部导入、宽松演奏或 Phase 5/6。

已完成项的实机证据针对已接入的 0.0.9.627 客户端。上传 MIDI 当前为音频媒体和黑屏演奏，试听不更新底部演奏栏；缓存范围见 Phase 4-2。首次从原版安装全部增量补丁仍需整合与验收，作为 Phase 7 安装交付的前置缺口跟踪，不能把已有启动包装器当作完整发行安装器。详见[游戏接入](./original-installation.md#当前交付边界2026-09-09)。

## 外部来源和版权边界

外部音乐服务通过可替换适配器接入，只保留统一的曲目中间表示和能力报告。实现只处理用户有权使用、能够合法导出的内容，不绕过 DRM、登录保护或地区限制；来源适配器不能写死进 MusicService。

Phase 4-6 的“宽松演奏”只要求歌曲能播放、MIDI 事件能驱动可用的演奏入口，不要求手指、琴键、镜头和动作逐帧一致。严格同步属于 Phase 5 的独立时间轴和可插拔 3D Renderer 工作。
